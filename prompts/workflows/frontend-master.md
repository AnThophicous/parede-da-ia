<phase_0_classify>
## Phase 0 — Classify (1 message, no questions yet)

1. Read the terrain without asking what you can find out yourself: `package.json`, framework, styling system, existing tokens, real content, brand (logo, fonts, colors).
2. Determine the **archetype** (router §3): corporate · personal/portfolio · ambitious.
3. If there is a reference:
   - URL → `web-url-fetch` + `web-wait-page-load` + `web-scrap` (+ `web-motion --observe 3`).
   - Video → `media-frames <file>` and read the contact sheets.
   - Screenshot → read the image and describe its visual DNA in 5 lines.
4. Announce the contract block (router §8) and move on to the matching Phase 1 branch.
</phase_0_classify>

<phase_1_elicit>
## Phase 1 — Elicitation (branched by archetype)

### 1.A Corporate → `workflows/corporate-briefing.md`
Full brief, an aesthetic chosen among the corporate families and extra questions on business, content, conversion, compliance and operations. **More questions, fewer assumptions.**

### 1.B Personal / portfolio → `workflows/creative-direction.md` (short mode)
Focus on personality: who the person is, 3 adjectives, the project they are proudest of, how daring to be, what the visitor should feel.

### 1.C Ambitious → `workflows/creative-direction.md` (full mode)
Core questions, always asked in ONE numbered message with suggested options:

1. **Central goal and visual climax.** What does the visitor need to do? What is the "wow" moment and where does it happen?
2. **Assets.** (a) generated in code (SVG, canvas, shaders, Three.js, Paper Shaders); (b) provided by the user; (c) taken from a reference (only with permission and respecting rights); (d) generated by an image AI (use `knowledge-base/09` §image prompts); (e) labeled placeholders.
3. **References.** Does the user have URLs/videos, or should you research Awwwards and propose **2 to 3 directions**?
4. **Constraints.** Mandatory stack, brand, deadline, performance budget (target device!), accessibility, languages, SEO, hosting.

### Phase 1 exit rule
Close with an **approved plan**: sections, initial tokens, stack, asset strategy, visual climax, acceptance criteria. Ask for an explicit "ok".
</phase_1_elicit>

<phase_2_build>
## Phase 2 — Build in slices (tracer bullet)

1. **Tokens first** (CSS custom properties or Tailwind's `@theme`): color, type, space, radius, shadow, **motion** (named durations and easings).
2. **Raw grayscale layout** with real content → hierarchy `[05]`, grid `[15]`, typography `[14]`.
3. **Color and texture** `[16]` → then **motion** `[12][13]` → then **microinteractions** `[11][18]`.
4. **WebGL/shaders last** `[17]`, always with a static fallback and `prefers-reduced-motion`.
5. Reuse the recipes in `library/` (gradients, hover font, magnetic, text morph, pixel trail, card stack) instead of reinventing them.

Forbidden:
- animating before the page works statically;
- effects without a purpose (every motion answers: does it orient, confirm, give continuity or delight at the climax?);
- locking content behind a preloader for more than 2.5s.
</phase_2_build>

<phase_3_verify>
## Phase 3 — Autonomous visual QA loop (repeat until the router §7 gates pass)

```bash
# 0. serve and open your own work
web-serve ./dist --detach --port 4173        # or the project's dev server
web-url-fetch http://localhost:4173 && web-wait-page-load   # preloader? web-wait 6 --until-hidden "#loader"

# 1. static evidence on 3 viewports
web-screenshot --viewports desktop,tablet,mobile --full-page --scroll-through

# 2. computed audit (0–100 score and verdict)
web-audit --viewports desktop,tablet,mobile

# 3. microinteractions of EVERY relevant interactive element
web-interactions --limit 15

# 4. motion: scroll choreography + easing vocabulary + jank
web-record-frames --while "scroll-down 6000 --steps 120 --interval 50ms" --interval 0.25
web-motion --observe 3 --while "scroll-down 2000 --steps 40"

# 5. visual regression between iterations
web-diff before.png after.png
```

For every image/spritesheet you read, look for:

| Category | Signals |
|----------|---------|
| Alignment | edges off the grid, icon off the baseline |
| Spacing | values off the scale, groups with inner space ≥ outer space |
| Typography | > 75 characters per line, widows, fallback font showing, hover font "jumping" the layout |
| Color | contrast from `web-audit`, accent overused (> 10% of the screen on corporate) |
| Responsive | horizontal overflow, CTA below the fold on mobile, targets < 24px |
| Motion | jumps between frames, layout shift, jank (`pageFrames.longFrames`), reveal before the scroll |
| States | missing hover/focus/active, or no transition |

Limit: 5 iterations. Still failing? Report it with evidence and a hypothesis.
</phase_3_verify>

<phase_4_deliver>
## Phase 4 — Delivery

Use `templates/delivery-report.md`: what was done, art direction decisions with the modules behind them, evidence (paths to the final captures and the spritesheet), the `web-audit` score, what the loop fixed (before → after) and known limitations. Finish with `web-close` and `web-serve --stop --port <port>`.
</phase_4_deliver>
